Cómo se identifica y autoriza a un usuario

Qué responde este diagrama: cómo la API sabe quién hace el pedido y si puede hacerlo, paso a paso desde que llega el token hasta que responde la ruta.

El diagrama

Abrir el diagrama a pantalla completa. Los textos fijos del visor (botones y leyenda) están en inglés; el contenido del diagrama está en español.

Mini glosario

Token de Firebase (JWT)
La credencial que el cliente obtiene de Firebase Auth y envía en Authorization: Bearer <token>. La API lo verifica con Firebase.
Firebase Auth
El servicio externo que emite y verifica las identidades. La API no guarda contraseñas.
Middleware
Un paso por el que pasa cada pedido antes de llegar a su handler (identificar, limitar, autenticar). Se ejecutan en un orden fijo definido en src/app.ts.
MongoDB
La base de datos. Es el único lugar donde se encuentran API y worker: el worker deja cosas ahí y la API las lee.
Límite de tasa
Un tope de pedidos por ventana de tiempo. Si se supera, la API responde 429 RATE_LIMITED.

Paso a paso

Cada paso indica quién lo dispara: el Cliente (alguien hace un pedido HTTP), el Backend solo (el worker actúa por reloj, sin que nadie pida nada) o Ambos. Los nombres de rutas, jobs, estados, colecciones y variables son los reales del código.

  1. 1

    El cliente obtiene un token de Firebase

    Lo dispara: Cliente

    El cliente inicia sesión en Firebase Auth (fuera de este backend) y recibe un ID token. En desarrollo, npm run auth:create-test-user crea una cuenta de prueba y npm run auth:token imprime un token.

    MongoDB
    Ninguna.
    Código
    src/scripts/createTestUser.ts src/scripts/authToken.ts
  2. 2

    Envía Authorization: Bearer <token>

    Lo dispara: Cliente

    requireAuth extrae el token del encabezado. Si falta, tiene otro esquema o supera los 4096 caracteres, responde 401 UNAUTHENTICATED sin consultar a Firebase.

    MongoDB
    Ninguna.
    Código
    src/middlewares/requireAuth.ts
  3. 3

    requireAuth verifica el token con Firebase

    Lo dispara: Cliente

    Llama a verifyIdToken de Firebase Admin. Resultados: token vencido → 401 TOKEN_EXPIRED; revocado → 401 TOKEN_REVOKED; usuario deshabilitado → 403 USER_DISABLED; otro código de autenticación → 401 UNAUTHENTICATED; Firebase no disponible → 502 FIREBASE_UNAVAILABLE. Solo DELETE /me y todo /admin/* piden además comprobar revocación (checkRevoked); en el resto no se consulta.

    MongoDB
    Ninguna.
    Código
    src/integrations/firebase/tokenVerifier.ts src/lib/errors.ts
  4. 4

    Se resuelve el usuario en MongoDB

    Lo dispara: Cliente

    resolveFromIdentity busca al usuario por firebaseUid. Si no existe, lo crea con rol user en ese mismo pedido. Si existe, sincroniza email y emailVerified si cambiaron y refresca lastSeenAt como máximo cada 5 minutos (LAST_SEEN_THROTTLE_MIN).

    MongoDB
    Lee y escribe users.
    Código
    src/modules/users/users.service.ts
  5. 5

    Límite por usuario

    Lo dispara: Cliente

    Después de identificar al usuario, un limitador por uid permite 120 pedidos por minuto (USER_RATE_LIMIT_PER_MIN). Al pasarlo: 429 RATE_LIMITED.

    MongoDB
    Ninguna.
    Código
    src/middlewares/userRateLimiter.ts
  6. 6

    requireRole autoriza según el rol

    Lo dispara: Cliente

    Solo las rutas de /api/v1/admin pasan por requireRole('admin'). Si el usuario no tiene rol admin, responde 403 FORBIDDEN. Las rutas de /me solo necesitan estar autenticado, y cada consulta se filtra por el userId del token, nunca por uno que envíe el cliente.

    MongoDB
    Lee el rol en users (ya cargado en el paso anterior).
    Código
    src/middlewares/requireRole.ts
  7. 7

    La ruta responde

    Lo dispara: Cliente

    Con la identidad y el rol confirmados, el handler responde (o devuelve el 403 del paso anterior).

    MongoDB
    Depende de la ruta.
    Código
    src/app.ts
  8. 8

    Los roles viven solo en MongoDB

    Lo dispara: Backend solo

    El rol no viaja en el token ni se cambia por la API: se asigna con el script npm run user:set-role -- --email ... --role admin, que lo escribe en users. Borrar la cuenta con DELETE /me elimina el perfil y sus datos, pero no la cuenta de Firebase.

    MongoDB
    Escribe users.role (por script).
    Código
    src/scripts/setRole.ts src/modules/users/users.service.ts

Cómo verlo en tu entorno

  • Levanta lo básico: docker compose up (MongoDB como replica set y Mailpit), luego npm run dev (la API queda en http://localhost:3000) y, en otra terminal, npm run dev:worker.
  • Consigue un token: en Postman, carpeta Auth (Firebase) → Sign up (create test user) y Sign in (get ID token), o npm run auth:create-test-user y npm run --silent auth:token. Usa un emulador de Auth o un proyecto de desarrollo, nunca producción.
  • Prueba los códigos: Me → Get my profile - no token -> 401 y Get my profile (el primer pedido crea tu perfil en users); Admin - Job Runs → List job runs - non-admin token -> 403.
  • Conviértete en admin con npm run user:set-role -- --email tu@correo --role admin y repite el pedido: ahora responde 200.
  • Importa crypto-tracker.postman_collection.json en Postman (variable baseUrl) o abre requests.http con la extensión REST Client de VS Code; ambos traen los mismos pedidos.
